# 无障碍采集与三种方式接入

日期：2026-10-14。版本：0.5.0（versionCode 6），已更新安装到手机。

## 用户决策与实施计划

用户要求先接入无障碍，产品提供无障碍、Shizuku + ADB、Root 三种方式，识别后直接入账，错误事后修正。

本阶段接入无障碍服务、系统授权状态、连接状态、受限页面识别与既有事务入账；自动页提供三种方式单选。Shizuku / Root 的真实后端分后续阶段接入，当前明确显示未接入并禁止开启，不能把三个入口视为三个后端已完成。

实施顺序：补充成功页面识别测试 → 注册只读 AccessibilityService → 将方式选择与队列接入共享采集运行时 → 更新自动页及文档。用户随后要求安装，并更新长期约定为完成功能默认构建安装。系统权限仍由用户授权，不提交代码。

## 已写入的实现

- 系统配置仅订阅支付宝与微信的窗口状态 / 内容变化事件，声明 BIND_ACCESSIBILITY_SERVICE、canRetrieveWindowContent；不请求手势、按键过滤或全窗口列表能力，不执行点击、输入、付款操作。
- 授权状态通过 AccessibilityManager 的已启用服务列表核对本应用组件，连接状态由服务生命周期回调提供。用户在系统无障碍设置开启“轻账无障碍记账”，回到轻账选择来源并开启采集。已授权但未连接时明确提示，不显示运行成功。
- 默认选择无障碍；首次引入方式选择时暂停采集。方式保存到应用私有 SharedPreferences，切换先暂停并使旧队列代次失效；处理时再次核对当前方式。旧通知监听仅保留为 Debug 回归入口，无障碍开启期间通知回调不会同时入账。
- 来源与全局开关均默认关闭。仅在所选支付来源前台页面变化时读取当前可见节点；密码节点及其子树跳过，包名再次校验。不读取其他应用节点，不使用通知事件作为页面内容。
- 每次读取最多 256 个节点、20 层、每层每节点最多 32 个子节点，单字段最多 512 字符、总文本最多 8 KiB；350 ms 延后合并连续回调。页面原文只在内存中预筛选，不写日志或数据库。
- 只接受明确“支付成功 / 付款成功 / 收款成功 / 到账成功”和唯一人民币金额、唯一方向；历史列表、退款、转账、充值、提现、还款及歧义页面不入账。纯“交易成功”没有方向时不推断。
- 可识别页面会话以来源、窗口、金额及方向维持，连续内容变化复用会话并由既有事务关联原账单，不覆盖用户修改。首次创建默认未分类、账户未指定、商户空，备注标注无障碍及识别时间。账单来源统一显示自动采集，用户可编辑或删除。
- 无障碍服务中断或销毁时暂停当前无障碍采集并报告可能漏记；不影响选中的其他方式。无网络传输，无 schema 升级，无历史候选追溯入账。

## 限制与验证状态

新增 4 项纯领域测试覆盖明确付款 / 收款、历史或聊天及未完成页面、多金额 / 退款 / 币种 / 失败混合文本。用户要求安装后，`:app:assembleDebug :core:domain:test` 执行成功（BUILD SUCCESSFUL，2m 7s），Debug APK 更新安装成功。未授予无障碍权限，尚未执行真实页面采集；此前 0.4.1 的数据库测试结果为旧版本证据，不宣称本次重跑。

真机入口检查：默认“无障碍 · 已选择”，显示“权限：未授权 · 监听：未连接”；选择 Shizuku + ADB 与 Root 分别显示尚未接入，再切回无障碍。默认采集保持暂停，未开启支付来源或设备权限。

最终核对安装包 versionName=0.5.0、versionCode=6；本轮领域测试共 20 项通过，应用进程 AndroidRuntime 错误日志未发现崩溃。UI 自动化寻找系统设置按钮时因滚动位置未找到，未执行授权操作；此项不算系统授权入口验收，待实际授权时继续检查。

静态检查：automation Manifest、无障碍服务配置与字符串资源共 3 个 XML 文件通过 System.Xml.XmlDocument 解析。此检查仅验证 XML 格式，不代表 Android 资源编译、Kotlin 编译或服务运行通过。

页面控件是否对无障碍暴露文字、实际包名、样式与版本覆盖仍需真机验证。当前为通用成功页启发式，历史详情可能包含成功文本；页面切换、短暂不完整布局、重访同一结果页或服务重启可能建立新会话并重复入账。不能承诺跨页面 / 跨进程交易去重，需要后续交易编号模板与脱敏回归样例。

无障碍只能读取系统允许暴露的页面，不保证后台交易或未展示页面可采集。服务被系统限制时不尝试绕过授权；用户可保持手动记账。

后续：先在真机授权并验证成功页与重复回调，再完善支付宝 / 微信模板、交易标识及跨会话去重；之后分别接入 Shizuku 的 Binder / ADB 身份和 Root 授权、能力检测及经验证的采集操作。ADB 权限不等于 Root，不承诺读取支付应用私有数据库。

## 官方接口依据

[Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.html) 与 [AccessibilityServiceInfo](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo) 说明窗口内容读取能力与服务配置。应用配置使用这一机制，不要求全部应用访问或手势能力。
