# 无障碍截图与本地 OCR 验收

日期：2026-10-21。版本：0.7.30（42）。数据库版本 4，无迁移。

## 本轮实现

新增有界截图门控和 Android 截图封装：节点为空、采集配置有效、来源窗口聚焦且屏幕交互 / 未锁屏时才尝试。Android 14+ 使用指定窗口接口，旧系统使用显示屏接口。配置或窗口变化丢弃结果，区分能力未生效、安全窗口、超时及近似纯色图像。异步截图和模型任务完成后关闭硬件缓冲、位图和识别器。

微信新路径使用随 APK 打包的 ML Kit 中文模型。成功状态、金额及相对位置通过独立领域规则校验，再只把标准化的状态和金额送入现有无障碍入账队列，复用配置代次、账户上下文和会话去重。截图和 OCR 原文不落盘、不上传；诊断只保留数量、位置及字符类别等元数据。支付宝页面仍不直接写账，保持到账通知口径。

按用户反馈，为账本加载 / 空状态卡片增加 16dp 顶部间距，避免紧贴概览卡。设计预览同步增加“账本（空状态）”以及截图 / OCR 诊断示例，沿用 miuix 风格。

## 问题复现与修复依据

- 门控的空页 / 当前来源 / 无效窗口 / 限频回归先失败再通过。
- 打包资源测试先复现缺少截图能力，再补齐主配置与 Debug 配置；不更改 `isAccessibilityTool=false`。
- 生成的中文测试图证明 OCR 可能把人民币符号读为 Y；真实截图证明符号也可能完全漏读。采用完整金额行校验和大字号 / 对齐约束，拒绝普通字号裸数字、多个金额和外币提示。
- 指定窗口图像会将成功图标识别为成功文字前的单个大写字符。通过字符类别和位置统计定位，再增加受大字号金额条件约束的处理；不接受额外中文、普通数字或多字母前缀。
- 最近任务切换的页面事件可能早于焦点稳定，增加最多三次 350ms 就绪等待；熄屏 / 非交互状态仍明确跳过，不自动开权限或绕过锁屏。

## 验证结果

领域 111 项通过；Android 16 项通过，包含真实截图的私有样本、本地中文模型、营销金额排除、位图释放、打包能力、错误分类和微信会话去重。真实截图只临时送入独立测试 APK 的私有目录，不提交到仓库；测试后删除样本并卸载测试 APK。未变更数据库实现，本轮未重跑数据库 instrumentation 套件。

正式 Debug 已构建安装。用户另完成一笔真实微信付款，保持成功页后验证：节点仍为 0 项文字，但应用自身截图接口取得 1200×2608 图像，OCR 返回 4 行文字，依次出现 RECOGNIZED、QUEUED、AUTO_POSTED。账单与采集记录由 0 / 0 变成 1 / 1，金额和支出方向与当前成功页一致，采集记录指向该账单。重复进入同一窗口后出现 DUPLICATE，数量仍为 1 / 1。未操作支付、优惠领取或返回商户按钮。

正式应用已核对账本金额与一笔流水、空状态间距、诊断入口、OCR 详情滚动与底部留白。进程未见 AndroidRuntime 崩溃。JavaScript 语法及预览筛选 / 诊断入口静态检查通过；未进行浏览器视觉验收。

## 未覆盖与限制

尚未实测 Android 11–13 的屏幕截图分支、其他手机 / 微信版本、安全窗口拒绝回调和深色付款页面。新 OCR 只覆盖微信付款支出成功页；商户和付款账户的 OCR 读取尚未补齐，本笔保留未分类及未指定账户。未知容器展示旧成功截图、跨重启重复打开同一成功页仍可能无法可靠区分，不能用金额与时间猜测合并不同交易。未实现 Shizuku / Root 截图或 Hook 后端；这些方案已记录在 [方案调研](automatic-capture-strategies.md)。
