# 支付宝支出与退款通知采集

版本：0.7.27（39），数据库版本 4，无迁移。

## 漏记原因与修复

旧版无障碍仅监听页面变化，通知监听只在旧通知模式工作；通知规则缺少“支出”方向，退款仍被拦截。现补齐截图中的两种通知：

- `交易提醒 / 你有一笔19.01元的支出，点此查看详情。` → 支出 19.01 元。
- `退款提醒 / 你收到一笔19.01元退款，点此查看账单详情！` → 退款 19.01 元，冲减支出，收入不增加。

支付宝使用专门的明确到账文案规则，月度支出汇总、退款申请、失败、处理中、领取提示和营销不入账。普通页面成功状态也收紧为独立状态行，并排除确认付款页，避免把“支付成功得绿色能量”广告误判成交易结果。

## 采集路径与防重

无障碍服务增加通知事件类型，直接读取事件携带的 Notification，不依赖当前窗口树。已授权并连接通知监听时，支付宝通知优先走监听通道；否则由无障碍通知事件处理。只接收已启用、已选中的支付宝来源，继续检查采集代次与用户范围；页面读取失败不会阻塞通知分支。

支付宝通知通常不含订单号。为避免按金额 / 时间误合并不同交易，本轮将支付宝到账通知作为唯一写账依据，支付宝付款 / 成功页不另生成账单。微信及测试器保留原有页面路径。因而支付宝通知被关闭或系统不交付通知对象时，单靠成功页面不会补记；不代表已覆盖所有支付宝版本。未补采升级前的历史通知。

正常带时间戳的通知使用来源、用户、通知时间、点击 Intent 标识、方向与金额组成哈希会话，同一通知更新 / 双通道投递复用会话；同额不同通知实例分别入账。无通知时间时退回各通道的实例标识。若平台重发时改变实例字段、进程重启后点击 Intent 标识变化，或未提供可区分的实例信息，仍可能重复或漏记，不能声称获得订单级防重；本轮不按金额 / 时间强行合并。

退款复用 REFUND 模型、净支出和账户余额口径；缺少订单号时不猜测原单，也不根据同额最近支出猜测退款账户。明确选中的付款账户可短暂关联支出通知，支持余额宝、支付宝余额及已有银行卡尾号规则；未暴露选中状态、多金额 / 多账户不确定时保留未指定账户，后续可编辑。不同方向的通知更新不会把退款并入支出。

Android 通知事件的 Notification 数据说明见 [AccessibilityEvent 官方文档](https://developer.android.com/reference/android/view/accessibility/AccessibilityEvent)。设备是否交付这些事件仍需实机确认。

## 验证

- 先用截图文案复现：新增领域测试最初有 4 项失败，修复后领域共 84 项通过；新增余额宝明确选中测试也经过失败后修复。
- 独立数据库测试 APK：59 项通过，覆盖退款自动入账与冲减支出、退款更新、同额独立退款、方向变更、既有防重及数据维护。
- 独立 Android 测试 APK：7 项通过，覆盖 Notification 对象经运行时入口的支出 / 退款识别、页面与通知防重、双通道重复、分组汇总与展开正文、来源 / 暂停隔离与 Live Updates 构造。测试使用隔离存储，不向正式账本添加样例。
- Debug 构建成功，0.7.27 已覆盖安装当前连接设备；设计稿已同步来源 / 方式说明，预览语法及原导航断言通过。
- 正式数据库八张业务表的逐字段指纹与测试前一致，账单 20 条（含删除记录）、采集记录 33 条；来源和配置不变。本轮应用进程 AndroidRuntime 错误查询无输出。
- 当前设备在页面检查阶段已锁屏，已请求用户解锁；启动指令与已安装版本确认完成，前台页面布局检查尚未完成，不能标记整套真机流程验收通过。

上述 Android 测试直接调用事件接收边界，不等同于支付宝实际发出通知再经系统送达无障碍服务。另一台手机暂不连接，真实付款、退款、系统事件交付、通知时间字段及其付款账户选中状态仍待用户复测。浏览器文件页面自动化受环境限制，本轮未做浏览器视觉验收。
