# 付款方式与资金账户识别

日期：2026-10-14。轻账 0.5.2（versionCode 8），支付测试器 0.2.0。

## 产品行为与实现

用户要求区分微信渠道下的零钱与银行卡。渠道来源包名与资金账户分开：来源仍显示支付测试器 / 微信，交易的 accountId 指向实际识别账户。

测试器首页新增单选：微信零钱、测试银行储蓄卡（1234）、测试银行储蓄卡（5678）、未提供付款方式。选择不产生交易；付款结果页展示最终选定的“付款方式”，收款页展示接收方的“入账账户：微信零钱”。失败页仍可显示选择项，但不会入账。

识别流程先拆出明确“付款方式 / 入账账户 / 到账账户”字段，再解析金额与方向，避免“付款方式”几个字把收入误判为混合方向。支出只用付款方式，收入只用接收方账户，不把付款人的银行卡当作自己的收入账户。

账户名称规范化：零钱映射为微信零钱；带明确银行名称、储蓄卡 / 信用卡类型及四位尾号的账户保留银行、卡类型和尾号。不同尾号分别记账。已有同名未归档账户复用；不存在的明确账户在账单事务内创建；同名已归档、冲突、多种付款方式或仅写“银行卡”时不猜测，也不恢复归档账户，保留未指定。

NotificationProposal 增加可选 accountName，默认 null 兼容旧解析；无需 Room schema 变更，账单沿用 accountId。原有编辑、来源保存、摘要重放和同会话保护继续工作。新增账户和账单共用事务，无原文持久化，无完整卡号采集。

## 当前边界

本阶段以成功页暴露的最终账户字段为依据，不把付款前的选择强行关联到后续不明确的交易。不跨页缓存选择，也不根据截图中绿色勾选的像素推断账户；真实微信的选择弹层、掩码尾号多控件布局、成功页无付款方式、组合支付仍需专门模板、可访问选中状态与可靠会话 / 交易标识适配。

账户字段如果晚于首次入账才出现，本版本不会覆写原账单或用户修改，用户可手动补账户。重命名后的账户无法仅凭名字自动确认身份时可能新建明确名称的账户，可在管理页人工整理。既有银行卡统称账户不会自动吞并具体尾号账户。
