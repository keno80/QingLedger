# 付款账户跨页面关联重新验收

日期：2026-10-14。轻账 0.5.3（versionCode 9），支付测试器 0.3.0。

## 修正目标

用户指出微信 / 支付宝的付款方式不出现在付款结果页。本版本改为付款确认页捕获当前账户，短暂缓存，成功后关联，而不是依赖结果页账户文字。0.5.2 的结果页字段验收仅作为历史记录，不再代表真实付款方式流程。

测试器首页进入独立确认页，提供零钱 / 测试银行储蓄卡（1234 / 5678）/ 未提供方式的 RadioButton。确认支付、模拟失败、取消本次均进入独立结果页，所有结果页都没有付款或入账账户字段。首页另有直接显示成功的回归入口，用于验证旧选择不会被带入没有确认阶段的新交易。

## 实现

- 可见节点快照保留有界文本，同时收集 isChecked / isSelected 的节点文字；只使用唯一可识别的选中账户，不因为某银行卡出现在选项列表就认定它已被选择。
- 确认 / 选择页必须能读到唯一交易金额和唯一账户才能缓存。余额 / 剩余字段不作为付款金额。选择变化更新缓存；未知或多选清除旧选择。确认阶段不入账。
- PaymentSessionCache 只保存一个内存中的待付款记录：来源、金额、账户、采集 generation 和单调时钟时间，不保存确认页原文，不跨进程持久化。
- 成功结果为支出，且来源、金额和 generation 相同、距选择不超过两分钟时，消费一次缓存。其他方向、金额、来源、开关代次或超时不匹配则不使用，并清除待付款记录。消费时检查有效期，不使用过期记录。
- 观察到取消、失败、普通首页或离开确认流程时清除缓存；服务中断 / 销毁同样清除。结果页重复回调沿用首次关联账户与同页会话，不重复消费或覆盖用户修改。
- 结构化账户随事件进入共享队列，事务入账继续复用 / 创建明确账户。结果页原文不增加缓存字段；内容摘要包含关联账户以支持事件元数据识别，无 Room schema 变更。

## 真机重新验证

使用用户已授权的无障碍服务，只开启模拟来源；通过截图和输入点击验证，不抓取会抑制无障碍服务的 UI 层级。基线为之前模拟账单：支出 ¥94.40，收入 ¥18.88。

| 场景 | 结果 |
| --- | --- |
| 确认页选微信零钱，成功页无账户文字 | 自动入账 ¥18.88，账户正确为微信零钱 |
| 从零钱改为卡 1234，尚未确认 | 不新增账单 |
| 改选后确认支付，成功页无账户文字 | 自动入账 ¥18.88，账户为测试银行储蓄卡（1234） |
| 同笔成功页刷新 5 次 | 总支出保持 ¥132.16，不重复入账 |
| 选卡 5678 后取消 | 不新增账单，支出保持 ¥132.16 |
| 取消后直接显示无确认页的成功 | 新增账单但账户未指定，不沿用旧卡 |
| 确认流程模拟失败 | 不新增账单，支出保持 ¥151.04 |
| 失败后直接显示无确认页的成功 | 新增账单但账户未指定，不沿用旧卡 |

最后支出 ¥169.92、收入 ¥18.88。本轮四条模拟支出保留供查看。两分钟超时、来源 / generation / 金额错配通过领域测试验证，未在手机上长时间等待或构造真实支付。截图保留在忽略目录 debug-artifacts。

结束时采集暂停，模拟来源和真实支付来源均关闭，两个主应用保留安装。轻账进程 AndroidRuntime 错误日志未发现崩溃；未提交或推送代码。

## 验收边界

这是测试器跨页面回调验收，不是微信 / 支付宝真实页面模板验收。实际应用的行选中状态、父子节点与掩码尾号拼接、零钱余额文字、组合支付、页面跳转仍需针对版本适配。

目前以单个已观察确认流程、来源、金额和有效期关联，尚无真实交易编号。若取消 / 切换事件未被系统暴露，或另一个相同金额的结果在有效期内出现，仍可能误关联；不能承诺唯一交易识别。无法读取确认页、选择过快未被采样、服务重启或超时则保留未指定账户，用户可修改。真实来源开关仍默认关闭。
