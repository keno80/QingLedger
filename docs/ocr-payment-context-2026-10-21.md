# 确认付款页 OCR 关联验收

初版：0.7.31（43），2026-10-21。确认页适配修正：0.7.32（44），2026-10-22。

## 行为

- 以微信确认付款页的付款方式字段为当前选择，无需打开付款方式列表。只读取推荐、优惠区域之前的唯一账户，银行卡支持名称与尾号换行及尾号斜线零。
- 商户、金额和账户仅暂存在内存。列表不覆盖缓存、不延长两分钟有效期；返回确认页的新选择会更新缓存。取消、失败、其他已识别页面和超时清除；短暂窗口不可读不立即视为取消。
- 成功页核对来源、配置代次、时限、金额及双方可读商户后消费一次。成功页商户优先，缺失时使用确认页商户。金额、商户冲突或过期时不关联账户。
- 不用账户余额、推荐卡或优惠金额入账。卡种不可读时仅保存明确的银行和尾号，唯一匹配已有账户；有歧义或账户已归档则保留未知，不猜测卡种。
- 商户随识别队列传递并保存到账单；确认信息本身不写账，不修改已有账单。数据库结构保持不变。
- 图片与 OCR 原文不保存、不上传；诊断只显示状态和是否取得字段，预览同步这些状态。

## 自动化验证

- 领域：123 项通过，覆盖钱包、银行卡尾号、推荐与余额排除、歧义账户、商户提取、时限、切换、取消、来源与金额冲突及消费一次。
- 数据库：61 项独立测试通过，覆盖确认不写账、成功后保存商户 / 账户、银行尾号唯一匹配与歧义不猜测。
- Android：19 项通过，覆盖生成确认页、真实私有确认页与成功页的 OCR 关联、队列字段传递及既有截图 / 通知回归。私有样本在独立测试 APK 内处理，没有向正式账本提交。
- 模拟中文字样出现过多字误读，合成测试商户改用稳定的拉丁字母名称；真实中文商户仍以私有页面样本独立断言。没有添加商户猜测或纠错规则来掩盖识别误差。
- Debug 构建与安装成功，独立测试 APK 已卸载。安装后正式账单和采集记录仍各一条，八张业务表指纹与修改前一致。

## 限制

本轮复用已获授权的确认 / 成功页面样本，没有发起新支付；不能把样本关联通过等同于完整新交易实测通过。更多手机字体、页面模板、Android 11–13、组合付款仍未验证。OCR 会误读，无法确定的字段保持未知；跨服务重启后重新打开旧成功页的可靠去重尚未解决。支付宝页面 OCR、Root、Shizuku 后端不属于本轮实现。

## 2026-10-22：带原价 / 优惠的确认页

0.7.31 的真机日志报告商户可读、账户未知。独立 APK 复用当前私有画面稳定复现：整页 OCR 把银行卡掩码星号读成汉字，账户区域放大可以读到独立尾号。修正为在已有合法确认信息时只采纳付款方式区域的新识别结果，保留原始金额、商户与字段位置；必要时以原始位置再次局部放大，不再用重试结果替换有效上下文。明确标注原价 / 优惠且同一行的附属金额不参与实付候选，未标注的多金额仍拒绝。

优惠目前不作为独立财务字段保存，也不计为收入。本次只保证实付金额用于账单与账户变动；优惠数据模型、详情展示及返现等状态处理留待后续实现。

新增当前私有确认页回归以及原价 / 优惠与未标注多金额的领域测试。原图和真实字段通过本地 instrumentation 参数提供，不提交到仓库。两种私有确认页额外核对银行名称与尾号；合成页面固定使用系统 Noto 简体中文字体，排除手机主题字体改变测试输入的影响，不改真实页面字体。

最新结果：125 项领域、61 项独立数据库、20 项 Android 测试通过；0.7.32 已构建安装，测试 APK 已卸载。真机保持当前微信确认付款页，经通知面板收起刷新，日志取得 PAYMENT_CONTEXT_CAPTURED，商户与账户均为 true；未点击支付或任何订单操作。当前有效账单 4 条、采集记录 5 条，新增和修改均早于本次测试开始；昨天的单条记录基线不能用于今天的完整数据比较。安装后按当前数据建立新基线，再次触发窗口刷新后八表指纹一致，没有提前写账，当前进程无 AndroidRuntime 错误。设备再次进入非交互状态时日志正确拒绝截图，不绕过此条件。

为保留用户付款页面，本轮未离开微信重走轻账主界面导航；新一笔真实付款的确认到成功全流程仍待用户正常付款验证。HTML 预览的脚本语法及自动记账入口静态断言通过，本轮未重跑浏览器交互验收。
