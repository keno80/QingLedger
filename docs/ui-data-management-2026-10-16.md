# 数据管理与本地备份恢复验收

日期：2026-10-16。版本：0.7.15（27），数据库版本保持 3。

## 设计与入口

从“我的 → 数据管理”进入，严格沿用已确认 HTML 中 data() 的布局和文案：

- 备份与恢复：创建本地备份、恢复备份。
- 导入与导出：导入账单、导出账单。
- 维护：隐藏已处理采集记录、数据清理。

页面使用 miuix Card / BasicComponent；恢复、导入来源及维护确认复用 LedgerBottomSheet，底部保留 24dp 内容留白及系统安全区。恢复确认的取消与覆盖按钮等宽；处理期间禁用重复操作和退出。

## 已交付行为

创建备份通过系统 CreateDocument 选择保存位置，生成带时间戳的 `.qlbackup` 文件；不申请整个存储空间访问权限。恢复通过 OpenDocument 获取用户选择的文件，完成校验后显示备份时间、未删除账单数、账户数与分类数，再由用户确认覆盖。

备份保存八张业务表：books、categories、accounts、transactions、transaction_edits、capture_configuration、capture_sources、notification_candidates。包括未知或已填写的账户初始余额、归档信息、软删除账单和修改历史；附带主题及采集方式设置。系统权限不随备份恢复。

恢复前用 AtomicFile 保存当前数据快照，之后通过单个 Room 事务替换业务数据。设置持久化在账单替换提交前完成，失败时尝试还原原设置；数据库替换失败则回滚账单，保留恢复前文件。发生进程中断时可从恢复入口导出最近恢复前备份。当前只保留最近一份恢复前文件，后续恢复会更新该文件。

恢复后采集保持暂停，增加采集 generation 以拒绝旧任务写入，清空跨页面识别会话缓存和撤销删除状态，重新加载账本、资产与搜索数据。不会替用户打开无障碍、Root 或 Shizuku 权限。

隐藏已处理采集记录复用已有操作并增加确认，仅隐藏已处理事件，保留账单与去重信息。平台账单导入、CSV 导出和按范围清理尚未实现，保留设计入口并显示说明。

## 文件约束

格式标识 `qingledger-backup`，文件格式版本 1，支持数据库版本 3；最大 16MB、总记录数不超过 20 万。采用 UTF-8 JSON 和 SHA-256 内容校验。校验用于发现损坏，不提供来源认证或加密，文件含明文财务数据，页面明确提示妥善保管。

读取时校验格式、版本、摘要、表集合、字段顺序、整数与空值类型以及结构深度；在独立内存数据库中验证主外键、账单规则、分类、账户及采集配置。拒绝不支持的版本和无效数据，不执行文件中提供的 SQL。保存失败明确提示重新创建，不报告成功；恢复会拒绝不完整文件。
