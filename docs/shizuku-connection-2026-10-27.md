# Shizuku 授权与连接排查

版本：0.8.1（48）。日期：2026-10-27。

## 两个独立问题

管理器显示“已授权 0 个应用”，不能单独用来判断轻账是否获得服务端权限。排查时安装包包含 `API_V23` 权限和 `V3_SUPPORT=true` 标记，Android 权限为允许，但 Shizuku 服务端最初返回未授权。用户重启服务并重新授权后，系统权限与实时服务端检查均返回允许；没有用 Android 权限或 SDK 正向缓存绕过服务端检查。

当前设备为 Android 17。Shizuku 官方已有同系统应用列表为空的报告：[Issue #2180](https://github.com/RikkaApps/Shizuku/issues/2180)。本机重启并成功连接轻账后，管理器仍显示 0 个应用，说明该列表不能作为连接是否可用的唯一依据。这是同类兼容问题的证据，未修改或替换用户的 Shizuku 安装包，也未证明本机上游故障的每个内部调用点。

之后出现的 `PatternSyntaxException` 属于轻账自身错误：窗口焦点和窗口条目正则中的字面量右花括号未转义，桌面 JVM 接受，而 Android ICU 拒绝编译。修正两处表达式，保持窗口所属包、安全标记和显示屏校验不变。UserService 版本升至 3，连接时替换旧实现。

## 验证

- 先在真机运行新增两项窗口解析测试，两项均在原表达式处抛出 `PatternSyntaxException`；修正后两项通过，包含安全窗口标记识别。
- Debug 构建成功，172 项领域测试零失败。0.8.1 已覆盖安装到连接的 Android 17 手机并正常启动。
- 使用本地私有 OCR 样本执行 Android 回归：报告共 46 项，其中实际通过 44 项，2 项独立测试包的 Shizuku UserService 测试因该包未获授权而跳过。未将跳过算作通过；测试样本已从设备清除，独立测试包已卸载。
- 正式轻账实际连接 Shizuku UserService，完成当前窗口和物理显示屏能力探测，页面显示“已连接”，实时服务端权限为允许。此证据与独立测试包的两项跳过分别记录。
- 自动记账保持暂停。13 笔有效账单、14 条采集记录保持，账本、分类、账户、账单、修改记录和采集记录的既有字段逐行一致。未操作真实支付或启用额外权限。

本轮没有让 Shizuku 截取微信交易页面，也没有完成新交易端到端入账；“已连接”只证明授权及能力探测通过。Android 17 管理列表问题仍属于外部兼容边界。

## 后续诊断

Debug 包增加由 `android.permission.DUMP` 保护的只读诊断接收器，分别返回 Binder、实时服务端权限、系统权限、支持标记和控制器状态。它不请求或授予权限，不输出交易内容，不在 Release 中注册。

```powershell
adb shell am broadcast -n io.qingledger.app/.ShizukuProbeReceiver
```

后续应以实时服务端权限、只读服务能力检查和实际采集结果共同判断；不能将授权弹窗出现、管理器计数或系统权限允许单独视为全流程已可用。
