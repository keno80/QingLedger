# 独立支付测试器与无障碍回归

日期：2026-10-14。轻账源码 / APK 0.5.1（versionCode 7），测试器 0.1.0。

## 目的与交付

按用户要求创建独立 Android 应用 payment-simulator，包名 io.qingledger.paymentsimulator，桌面名称“支付测试器（模拟）”。界面参考微信成功页的绿色、留白和金额层次，所有页面明确标记为模拟，不使用微信包名，不发生真实交易，无网络权限。

测试首页输入金额，提供付款成功、收款成功、付款失败和多个金额四种场景；成功 / 失败页是实际 TextView 控件，供无障碍读取，不是截图。重复刷新按钮仅更新刷新次数，用于验证同页内容变化不会重复创建账单。返回首页后可继续测试另一交易。

## Debug 来源隔离

轻账 Debug AppContainer 的数据库来源白名单及运行时无障碍白名单增加模拟包；Debug 无障碍配置 XML 同样增加该包，系统事件过滤、运行时和事务层均需匹配。Debug queries 声明可见该包，来源页面显示模拟标签，开关默认关闭。

Release 白名单和服务 XML 不增加模拟包，模拟器本身不生成 Release 变体。原支付宝 / 微信来源设置不被自动开启。无 schema 变更，无真实支付应用安装前置要求。

## 构建与安装

`:app:assembleDebug :payment-simulator:assembleDebug :core:domain:test` 构建成功（46 秒）。两个 APK 均已更新安装到设备 797e378f，测试器可独立启动。

新增 2 项测试器页面文本回归，验证收款方向不被页面标题误判，以及失败 / 多金额页面拒绝入账。`:core:domain:test` 重新执行成功（7 秒），累计 22 项领域测试通过。

用户已授权并重新开启无障碍。调试发现 UI 层级抓取工具使用 UIAutomation，默认会抑制其他无障碍服务，触发轻账的断连暂停，因而产生“已授权但未连接”。停止层级抓取，改用截图与输入点击后回调正常；不通过 ADB 修改系统授权。参见 [Android UiAutomation](https://developer.android.com/reference/android/app/UiAutomation) 的 FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES 说明。后续无障碍集成测试应使用不抑制服务的自动化，或截图输入方式。

## 真机结果

仅启用模拟来源，支付宝 / 微信来源保持关闭。测试器的可见控件触发真实 AccessibilityService 回调并经现有事务入账，没有向数据库注入测试交易。

| 场景 | 结果 |
| --- | --- |
| 模拟付款成功 ¥18.88 | 自动生成一笔支出，备注标明无障碍及识别时间 |
| 同页刷新 5 次 | 仍只有一笔支出，支出汇总 ¥18.88 |
| 模拟收款成功 ¥18.88 | 自动生成一笔收入，收入汇总 ¥18.88 |
| 模拟付款失败 | 不新增账单 |
| 成功页同时显示 ¥18.88 与余额 99.99 元 | 不新增账单 |

失败及多金额测试后，汇总保持支出 ¥18.88、收入 ¥18.88、结余 ¥0.00。本轮保留两条模拟账单供用户查看；来源为支付测试器，可编辑或删除。测试结束暂停采集并关闭模拟来源，保留两个已安装应用供继续测试。真实应用模板、跨进程与历史页重访去重不在本轮验收范围内。截图保存在 Git 忽略的 debug-artifacts 目录。

最终截图显示无障碍已授权、监听已连接、采集已暂停。两个应用进程的 AndroidRuntime 错误日志未发现崩溃，未提交或推送代码。

## 手动复现

1. 系统设置开启“轻账无障碍记账”，轻账自动页选择无障碍，确认已连接。
2. 开启“支付测试器（模拟）”来源和采集，保持真实支付来源关闭。
3. 打开测试器，设置金额后点击模拟付款成功；回轻账检查支出及来源。
4. 回到同一结果页重复刷新，确认账单数量与汇总不增加。
5. 返回首页模拟收款，检查收入；再测试失败及多金额，确认不入账。
6. 暂停采集并关闭模拟来源；测试账单可通过编辑、删除与撤销处理。

这组测试验证真实无障碍事件到 Room 入账的闭环，不证明真实微信或支付宝页面适配。跨进程、重访历史成功页和交易编号去重仍需后续验证。
