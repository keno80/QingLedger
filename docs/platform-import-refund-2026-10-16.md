# 平台账单导入与退款验收

日期：2026-10-16。版本 0.7.21（33）。数据库版本 4。

## 交付范围

“我的 → 数据管理 → 导入账单”中的微信支付、支付宝入口已接入文件选择、预览、分类与账户匹配和确认事务入账。微信支持单工作表 XLSX / UTF-8 CSV；支付宝支持 GBK / GB18030 / UTF-8 CSV。保留轻账 CSV 的既有入口，页面继续使用 miuix Card、BasicComponent、Button、分段控件和统一底部弹层，HTML 预览已同步。

文件限制 16MB / 50000 笔。XLSX 使用有界 ZIP + SAX 读取共享字符串、内联字符串、数值单元格及 Excel 日期；交易单号保留文本精度，已转为超长数值或科学计数法的 ID 拒绝导入。公式行、DTD / 外部实体、损坏文件、多工作表、过长字段及超限内容会明确拒绝，不执行公式或外部资源。解压后总内容上限 64MB、单条目 16MB、条目数 256。

平台说明区在表头前跳过，账单表头按字段名称定位；金额使用整数分、时间按 Asia/Shanghai 解释，Excel 时间按秒还原。使用平台命名空间与原交易单号的 SHA-256 生成稳定账单 ID，重复文件及重叠日期导出按 ID 跳过，软删除 ID 不恢复，不覆盖用户修改。

## 状态与账户

- 支付宝支付成功、交易成功、已付款等待收货等收支记录正常解析。明确为支出、仍有付款方式的已退款关闭原单保留；退款成功记录转为退款。普通关闭、冻结、还款及其他不计收支记录列出跳过原因。
- 微信保留原支出金额，包括显示已全额 / 部分退款的原单；退款明细单独识别为退款，不再次按状态中的退款金额扣减原单。给他人的微信转账遵循文件中的收支标记，不假定是用户自己的两个账户之间转账。
- 零钱、零钱通、支付宝余额、余额宝、花呗和不同尾号银行卡分别映射账户；银行卡名称与现有自动识别规范一致。支付宝 `&优惠` 等附加优惠不作为账户；包含多个真实资金账户的组合付款报无效，当前不自动拆分金额。
- 未知状态不会猜测为成功。未知分类 / 账户仍由用户在原匹配面板中选择使用、新增、恢复或不设置。新增账户初始余额保持未知。

## 退款口径与约束

用户已确认采用“退款冲减支出”，参考 [MyExpenses 官方分类说明](https://github.com/mtotschnig/MyExpenses/wiki/FAQ:-Data) 的退款统计口径，自行实现，未复制第三方项目代码。

退款使用独立 `REFUND` 类型与正数金额，按实际到账月份扣减净支出，增加到账资金账户余额，不增加普通收入。原支出完整保留。跨月退款可能使退款月份净支出为负，这是当前现金发生日期口径。

退款分类使用支出分类。平台文件内只有商家订单号明确相同、原单唯一、交易对方相同且退款时间不早于支出时才自动关联；无充分证据不按同额、同商户猜测。未匹配的退款保持独立，可选择分类后入账，后续在编辑页人工关联。手动关联选择器显示当前账单列表中的支出及日期、账户；需要其他月份的原单时先切换账本月份。

关联原单必须为未删除支出，分类一致，累计退款不能超过原支出金额。编辑金额 / 类型 / 分类、删除原单和撤销退款删除都会重新校验；删除原支出前需先删除关联退款或解除关联。导入预览提供解除关联操作，随后重新校验。提交时再次检查全部数据，引用创建 / 恢复、账单和修改历史在一个 Room 事务中写入，中途失败回滚。

## 迁移、备份与导出

Room 3→4 仅增加 nullable `originalExpenseId`，既有账单此字段为空。备份新写版本 4，旧版本 3 经校验后补空字段再恢复；退款关联与分类、金额也纳入备份校验。

轻账 CSV 新版列顺序为旧 13 个业务字段、`原支出ID`、`文本转义`，共 15 列。文本转义使用 `v3:` 加需要去掉保护单引号的零起始列号，以分号分隔；退款类型和关联可往返。兼容旧版 14 列 `v2:` 和 13 列无标记文件，后者继续保留原文本单引号。

## 当前边界

重复检查基于平台交易单号 / 轻账 ID，尚不能自动识别与此前手动或无障碍生成但没有平台单号的账单重复，导入前需核对。没有实现组合付款金额拆分、跨文件商家订单号匹配、自动退款采集或多工作表 XLSX。未在正式账本按最终确认写入（独立数据库批量写入及回滚已验证），未验收 50000 笔真机性能和云文件提供程序异常。数据管理中的按范围清理仍未实现。
