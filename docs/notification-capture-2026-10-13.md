# 通知采集与候选验收记录

日期：2026-10-13。版本：0.4.0（versionCode 4）。设备：24053PY09C / chenfeng，Android 17（API 37），HyperOS OS4.0.0.15.XPACNXM。

## 交付范围

通知监听服务通过系统通知访问授权接收回调。自动页展示授权与连接状态，提供独立全局开关、支付宝 / 微信来源开关及暂停功能。初始与数据库迁移后全部关闭；监听中断暂停并提示可能漏记，不擅自补授权。

本地关键词预筛选提取人民币金额和可能的收支方向。验证码、优惠及明确失败通知过滤；多金额、未知方向、转账和退款等要求核对。所有来源模板未经真实支付验证，全部候选需要人工确认，不执行自动入账。退款与其他币种不直接确认入账。

候选支持核对金额、类型、时间、分类、账户与备注后入账，或者忽略。确认事务同时记录来源，重复确认返回原账单。相同通知会话和内容摘要用于重放去重；同额同方向且两分钟内的账单仅作为疑似重复建议，用户明确关联才能合并处理，原账单不被覆盖。相同金额的不同交易可以独立入账。

## 数据与隐私边界

- Room schema 从 v1 升为 v2，显式 MIGRATION_1_2 保留旧账单，并增加来源字段、采集配置、来源开关和候选表。
- notification_candidates 合并结构化事件及候选，保存来源包名、用户空间标识、来源版本、接收时间、金额、方向、原因、处理状态、账单关联和 SHA-256 会话 / 内容摘要。不保存原始标题、正文或聊天内容，不自动填充商户。
- 正文只进入最多 128 项的内存队列，单项最多 8 KiB；未选来源不入队。处理时再次核验全局 / 来源开关及 generation，暂停或切换来源后旧队列失效。
- 列表优先展示待确认事件，最多 200 项，待确认数量单独统计。隐藏已处理事件保留摘要，避免已处理事件重放；不等同物理删除。保留期限与清理任务尚未实现。
- 会话映射存于进程内，移除通知会结束会话。进程重启或来源重新发布通知可能生成新候选；不扫描历史通知、不回填中断记录。跨会话去重仍依赖人工核对，不保证全部重复都能识别。
- Debug 版独立开放 com.android.shell 的“ADB 调试样例（非支付通知）”，Release 来源白名单不含此项。应用没有 INTERNET 权限。

## 已执行验证

Debug APK 构建成功并更新安装，旧账单未清空。领域测试 16 项、真机数据库及迁移测试 17 项通过。

测试覆盖金额 / 日期 / 引用规则、通知预筛选和歧义处理，以及默认关闭和来源白名单、开关代次失效、同会话摘要重放、确认幂等、删除或隐藏后去重、无效草稿回滚、疑似重复人工关联、不同同额交易、退款更新不可绕过拦截、v1→v2 保留账单。

用户明确选择“现在授权并验证连接”后，在手机系统设置为轻账开启通知访问。返回自动页显示“通知权限：已授权 · 监听：已连接”。支付宝 / 微信来源保持关闭。

仅开启 Debug 样例来源，通过系统 `cmd notification post` 发布“支付成功12.34元”，监听实际收到并生成 ¥12.34 待确认事件。人工填入测试标题 QL_DEBUG_CAPTURE 后确认，账单详情显示“ADB 调试样例（非支付通知）通知候选（人工确认）”。这证明系统回调到候选及入账闭环，不证明支付宝或微信适配。

再次发布同标签样例出现第二条候选，没有自动新增账单。系统发布涉及新会话时不能按同会话重放断言，UI 验收不宣称该次被摘要去重；同会话重放与确认幂等以数据库测试为证据。第二条候选人工忽略，测试账单软删除，保留原有用户数据。

最终状态：通知访问保持用户授权，监听已连接；采集暂停，支付宝、微信及 ADB 调试来源均关闭，待确认 0 条，已处理样例隐藏。独立数据库测试 APK 已卸载；应用进程 AndroidRuntime 错误日志未发现崩溃。代码与文档未提交或推送。

## 未验证与后续任务

真实支付宝 / 微信支付、收款、撤销等通知模板与 versionCode 覆盖尚未验证；当前用户空间支付宝可见、微信查询未安装，安装状态不等于交易支持。关键词预筛选可能产生误识别，需用户逐笔核对。

下一步采集经用户授权的脱敏来源样例，建立按应用版本管理的规则和回归样例，验证金额、方向、商户、交易时间及同会话更新，再决定能否开放高置信自动入账。Root / Shizuku、退款关联、后台持续运行、多用户空间、其他系统、200% 字体和读屏仍待验证。
