# 微信窗口读取排查与加固

版本：0.7.29（41），数据库版本 4，无迁移。

## 实现

- 将节点遍历提取为可测试的有界读取器。不可见容器自身的文字不采集，但继续检查它的可见后代；已验证来源的子节点未声明包名时允许继承来源。显式异来源和密码子树仍被排除，根节点必须明确属于当前来源。
- 声明交互窗口和非重要视图读取标志。按事件所属逻辑屏幕查询应用窗口，仅处理所选来源包的根，最多读取 4 个根，每根受节点 / 深度 / 文字长度限制。不读取其他应用的子树。
- 各窗口独立判断，不拼接不同窗口的状态和金额；多个窗口识别到不同交易方向或金额时拒绝入账。空覆盖窗口可回退到同屏同来源的单一成功页。
- 诊断增加屏幕、窗口、范围、候选数、节点数、隐藏 / 异来源 / 未标来源 / 密码 / 敏感标记计数、根子节点数与最多 4 种节点类型。保留原有 miuix 面板，增加详情文字，设计预览同步。
- Debug 日志输出同一份固定元数据，并沿用短时去重。不输出页面原文、账户、商户或交易金额；不启用 UI 自动化转储、OCR、Root、Shizuku，不更改 `isAccessibilityTool` 声明。

窗口 API 和标志依据：[AccessibilityService 官方文档](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[AccessibilityServiceInfo 官方文档](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo)。

## 验证

旧遍历条件在两个回归场景中复现失败：隐藏容器下有可见成功页、子节点没有包名。修改后领域共 97 项通过，包含密码 / 异来源隔离、根来源校验、有界遍历、空覆盖窗口回退、冲突拒绝及跨窗口不拼接。

Android 共 10 项通过，新增打包配置断言，确认 Debug 资源同时包含交互窗口 / 非重要视图标志与通知事件类型。Debug 构建及安装成功，临时 Android 测试 APK 已清理。正式应用启动、诊断入口、长详情滚动和底部留白已在真实测试手机核对。JavaScript 语法与预览筛选 / 诊断入口检查通过，未完成浏览器视觉验收。

未修改数据库实现，本轮未重跑数据库 instrumentation 测试。正式应用查询账单和采集记录均保持 0，自动记账与微信 / 支付宝来源仍开启，应用进程无 AndroidRuntime 崩溃记录。用户未再次付款，本轮复用之前保留的成功页；查看最近任务并恢复该页，不点击支付或商户操作按钮。

## 实际结果与结论

真实成功页重测读到：逻辑屏幕 0、单个同来源应用窗口、根范围与手机完整屏幕一致、遍历 2 个 FrameLayout 节点、其中 1 个隐藏、根有 1 个子节点、异来源 / 未标来源 / 密码 / 敏感标记计数均为 0、可读取文字仍为 0。

由此可区分：根并非完全不存在，没有因异来源或缺少包名被剪掉的子树；本次 API 返回范围内没有发现另一个承载结果的同屏微信窗口。修复的过滤缺陷在回归构造中成立，但不是本机这张页面恢复文字读取的充分条件。当前接口仍未提供足够的文本节点，实际自动入账仍未成功，不能宣称微信支付已经修复，也不能推广为所有微信页面永久不可读。

下一步若要支持这类页面，需要另外设计本地 OCR 或可靠交易通知兜底。当前真实流程未收到可用微信交易通知；本轮未擅自新增截图能力或系统授权。成功页附带营销金额的解析尚未走到，仍需在取得文本后验证。
