# 微信页面识别与采集诊断验收

版本：0.7.28（40），数据库版本 4，无迁移。

## 修改范围

采集记录增加 miuix 诊断卡片和底部面板，显示当前无障碍授权、连接和采集状态，以及最近事件的来源、时间、阶段、拒绝原因和可见文字项数量。诊断保留本进程最近 40 条，2 秒内相同状态去重，不持久化，也不保存页面原文、商户、金额、账户或密码。进程重启后清空；系统没有把事件送达服务时，不能从空记录推断支付未发生。

阶段涵盖事件接收、页面读取、规则判断、入账队列、入账结果、重复抑制与错误。原因区分未启用来源、暂停、窗口不可取、窗口来源不符、空页面、无成功状态、多金额、缺少金额、方向冲突、付款确认、历史与不支持路径。微信通知仍未接入自动记账，收到通知事件时明确显示此限制。

页面识别支持成功状态与金额合并为一个节点，如“支付成功 ¥19.01”“付款成功19.01元”，也支持成功状态附近唯一的独立两位小数金额。兼容不换行空格，仍拒绝多个金额、远处数字、裸整数、营销成功文案、确认付款页、历史及方向冲突。未根据未知真实页面猜测商户和账户。

## Debug 通知事件配置修复

检查发现 Debug 专用无障碍 XML 覆盖主配置，却未声明 `typeNotificationStateChanged`，因此 0.7.27 Debug 在仅使用无障碍时可能收不到支付宝通知。已同步修正，并新增读取实际打包资源的 Android 回归断言。此测试先复现失败，再在修复后通过。0.7.27 的运行时单元边界测试不能证明系统事件已经送达，之前验收文档中的限制仍成立。

## 验证结果

- 新页面格式测试先复现 3 项失败，修复后领域共 90 项通过，包括明确拒绝原因。
- Android 共 10 项通过，新增诊断来源隔离、容量限制、短时去重、入账及重复阶段、实际打包事件类型检查；支付宝既有通知和 Live Updates 测试继续通过。临时运行时测试 APK 已清理。
- Debug 构建成功，已覆盖安装当前手机。用户手动授权无障碍后，正式应用显示运行正常。
- 真机只操作已开启的支付测试器：付款确认页和多金额结果页，未操作真实支付。诊断面板实际展示“收到页面变化事件 → 已读取 11 项文字 → 存在多个金额，无法确定交易金额”，卡片、滚动面板及底部留白正常。未新增模拟账单。
- 正式数据库八表逐字段指纹不变：账单 20 条（含删除记录）、采集记录 33 条，来源和采集设置保持原值。应用进程 AndroidRuntime 错误查询无输出。
- HTML 设计预览同步诊断入口与示例面板；JavaScript 语法、记录筛选数量和诊断入口断言通过。预览检查脚本调整为只统计账单行，避免将新增诊断入口算作账单。
- 本轮未变更数据库实现，未重跑数据库 instrumentation 测试。未完成另一台手机真实微信付款页面适配、微信通知兜底、真实支付宝通知系统投递及浏览器视觉验收。

## 复测方法

安装新版后确认“无障碍已连接”和微信来源开启。在微信完成支付后返回“我的 → 设置 → 自动记账 → 采集记录 → 采集诊断”，查看该时间段的阶段与原因；可提供面板截图，帮助进一步定位实际页面差异。诊断需要在同一次应用进程运行中查看。
