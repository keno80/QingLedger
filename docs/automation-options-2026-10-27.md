日期：2026-10-27。版本：0.8.0（47）。设计依据为已确认的自动记账选项提案，现有直接入账继续保留，并作为旧配置迁移后的默认值。

后续 0.8.1 已重新构建安装、执行此前新增 Android 测试，并在正式应用验证 Shizuku 授权和窗口 / 显示屏能力探测通过；真实交易图像及跨应用悬浮窗仍待补验。以下保留 0.8.0 阶段记录，最新证据见 [连接排查](shizuku-connection-2026-10-27.md)。

## 实现范围

- 今日收支通知：按账本时区观察当日真实收入、支出，退款冲减支出，账户转账不计收支。独立开关、低打扰频道和前台服务；锁屏公共版本隐藏金额。点击通知进入今日所在月份账本。
- 确认后入账：识别内容先保存为待确认，不创建资金账户或影响账本。金额、入账类型、分类、账户、商户、原价、优惠及备注可编辑；确认时使用当前时间。取消、关闭、返回和点击遮罩均舍弃，并保留重复抑制关系。现有账单编辑的日期和时间功能不变。
- Shizuku + ADB：接入独立 UserService，只读检测当前窗口并获取微信交易页面图像，复用本地 OCR、账户上下文和持久化交易会话；不要求开启轻账无障碍。支付宝仍需独立通知访问提供明确交易 / 退款通知。Root 后端尚未实现。
- Room 5→6 增加配置及结构化待确认字段，备份支持 3 / 4 / 5 / 6，恢复后暂停采集。确认操作与识别账户创建在同一数据库事务完成。

## 弹窗对齐修正

商户、原价、优惠和备注输入值统一右对齐，并与分类、资金账户的值共用右侧内容边线。没有箭头的输入行保留与选择行箭头区域相同的 20dp 空间，左侧标签宽度一致；取消和确认按钮等宽。保留 miuix TextField，仅局部调整其内部编辑区域对齐，不改变整个表单的布局方向。

同步更新 `qingledger-ui-preview.html` 的确认弹窗与新增设置。浏览器设计示例不操作真实账本或授予系统权限。

## 开发验证包

`gradlew :app:assembleDebug '-Pqingledger.qa=true'` 可生成独立应用 ID `io.qingledger.app.qa` 的验证包。默认构建仍为正式应用 ID。模拟确认接收器仅在 Debug 存在，且校验验证包 ID，不能向正式包生成模拟账单。授权由用户手动执行；设备不可用时保留未验证项。
