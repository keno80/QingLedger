# 微信、支付宝账单与退款实现计划

目标：支持用户提供的支付宝 GBK CSV 和微信 XLSX，沿用现有 miuix 文件预览、引用匹配、确认事务导入。

已确认口径：退款单独记录，冲减实际退款月份的支出，不增加收入；原支出保留。退款使用支出分类，可按明确订单号关联原单。匹配不唯一时不猜测，可独立归类；关联退款累计不能超过原支出。支付渠道与实际资金账户分离，优惠不作为账户。转给他人的微信转账按来源标记收支；冻结、还款等“不计收支”记录显示跳过原因，不伪造账户间转账。

- [x] 先编写退款汇总、余额、关联约束、CSV 往返及平台格式测试，执行确认缺失功能。
- [x] domain：新增 REFUND、原支出 ID、退款验证；解析支付宝 CSV 和微信表格记录，稳定平台订单 ID、状态与账户标准化、退款匹配、跳过与错误行。
- [x] data：受限 ZIP / SAX 读取 XLSX（共享字符串、内联字符串、Excel 日期、拒绝公式和损坏/超限文件），数据库 3→4 保留既有字段；旧版备份适配，导出增加原支出列并兼容旧 CSV。
- [x] app：来源入口复用导入页，微信支持 XLSX/CSV，支付宝支持 GBK/UTF-8 CSV；退款详情/编辑/列表与汇总一致，保留统一 miuix 组件。
- [x] 独立数据库验证整批写入、退款重复/超额/删除/编辑约束、回滚、迁移及备份恢复；原文件只做本地解析核对，使用脱敏文件进行真机预览与取消。
- [x] 同步 HTML 预览与验收文档，构建安装并测试，确认正式账本未变化，暂存全部改动后中文 Conventional Commit 并推送。

实现顺序在当前会话内推进，避免并行修改同一数据模型。
