# 支付宝通知与退款采集修复

用户已批准开始补齐支出通知、退款与跨渠道防重。本轮使用头脑风暴梳理数据流，按 TDD 先复现漏记，再修改规则。

## 方案

支付宝以明确到账的通知作为入账依据；确认付款及成功页面用于账户上下文，不另写账单。无订单号时不按金额 / 时间猜测合并。通知访问已授权并连接时使用 NotificationListener，否则从无障碍的通知事件读取通知对象；两者均不读取通知栏其他应用文字。微信保留原页面路径。

支出适配“交易提醒 / 你有一笔19.01元的支出”，退款适配“退款提醒 / 你收到一笔19.01元退款”。仅明确到账退款记 REFUND；申请中、失败、营销与待支付不入账。退款不猜测原支出，无单号时保留未关联与未指定账户，后续可编辑。通知重复与更新按来源、通知实例与业务方向去重；不同通知实例的同额交易保留。退款复用已有模型和统计，无数据库迁移。
