# 确认付款页 OCR 上下文实现计划

目标：按用户确认的流程，从确认付款页读取金额、商户、当前付款账户；付款成功后核对关联，不要求打开付款方式列表。

按当前工作区顺序实现，不使用并行代理。

- [x] 领域测试先覆盖银行卡名称 / 尾号换行、钱包、推荐卡排除、列表不覆盖、歧义账户及成功页商户提取；运行红灯后实现规则。
- [x] 新增有时限的结构化上下文缓存，测试账户切换、列表保留但不续期、取消 / 失败 / 超时 / 金额或商户冲突清除。
- [x] OCR 输出结构化确认信息；服务只暂存确认页，成功后关联账户和商户；已有节点采集保持兼容。
- [x] 通过入账队列传递商户，数据库仓库在创建账单时保存；补独立数据库测试证明商户 / 账户与账单关联，不提前写账。
- [x] 通过用户已授权采集的私有截图和测试器 / 生成页面验证实际中文识别，原始图像不提交到仓库。
- [x] 更新版本、诊断和设计预览，构建安装，核对真机日志和既有数据，记录未验证范围。
- [x] 更新文档，暂存所有改动，中文 Conventional Commit 后直接推送。

设计：确认页需同时满足付款方式字段与付款操作提示。只读取该字段下、推荐优惠区域前的唯一账户；无法确定时保留未知。列表页不修改缓存。缓存按来源、配置代次、两分钟时限、金额及可用商户交叉核对，消费一次。成功页商户优先，确认页作为缺失时补充。取消或识别为其他页面时清除；窗口暂时不可读不当作取消。图片和 OCR 原文只在内存处理，诊断只报告状态及是否取得字段。

补充：卡种不清时仅保留银行与尾号，唯一匹配已有账户；明确原价 / 优惠不作实付候选。0.7.32 真机确认页已取得商户与账户，125 项领域、61 项数据库、20 项 Android 测试通过。保留用户付款页，主界面导航未重跑；未发起新支付，完整新交易仍待正常使用验证。详见 [验收补充](../../ocr-payment-context-2026-10-21.md)。
