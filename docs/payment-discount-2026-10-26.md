# 付款优惠记录验收

版本：0.7.33（45），2026-10-26。方案于 2026-10-22 开始实施，收尾验证于 2026-10-26 完成。

## 行为与界面

- 支出增加可空的原价、优惠金额，实付仍使用原金额字段。没有识别到的字段保持未知；明确的零优惠保存为 0。余额、收入、支出、退款上限均按实付计算，优惠不作为收入。
- 原价不能小于实付；两项均存在时，原价减优惠必须等于实付。手动编辑、导入、备份恢复均校验；原价与优惠冲突的 OCR 辅助信息丢弃，主交易仍按有效成功信息处理。
- 微信确认页只读取明确标注的原价和已应用优惠，随来源 / 配置 / 金额 / 商户 / 两分钟时限的上下文匹配成功页后入账。原价、优惠不作为实付候选；推荐、待领取、返现、积分、折扣比例、分期期数和优惠券余额不作为已减金额。支付宝通知没有提供这些字段时保持未知。
- 详情保留实付大金额，有辅助金额时增加原价、优惠信息行；没有数据时不增加空行。编辑的支出信息卡增加“优惠信息”入口，复用 miuix 底部面板、两项可选输入及等宽取消 / 确定按钮。取消面板保留草稿，普通编辑保留字段，可手动更正或清空；切换到非支出时清除草稿优惠。
- `qingledger-ui-preview.html` 同步详情、编辑面板、校验与诊断示例。

## 兼容与迁移

Room 4→5 增加 `originalAmountMinor`、`discountMinor` 两列可空 INTEGER，不回推历史优惠。备份仍使用外层格式 1，数据库版本写 5，兼容数据库版本 3 / 4 的备份并补空字段。恢复前备份、隔离校验和事务回滚保持原流程。

新轻账 CSV 为 17 列，增加原价 / 优惠两列，文本保护标记为 v4；继续读取 13 / 14 / 15 列与 v2 / v3 文本保护。旧文件不推测优惠；新文件保留未知与零的区别，非法字段逐行报错。微信 / 支付宝平台账单导入仍使用原口径，没有明确原价 / 优惠时不从备注推算。

## 自动化验证

- 134 项领域测试通过：辅助金额范围与一致性、营销数字排除、OCR 原价 / 优惠提取、重试合并、缓存关联、CSV 新旧往返、公式转义与退款 ID。
- 66 项独立数据库测试通过：4→5 迁移、实付统计与余额、保存 / 普通编辑 / 清空、成功采集与重复抑制、CSV 导入导出、备份恢复、旧 3 / 4 备份及非法优惠拒绝。
- 20 项 Android 测试通过：用户授权的私有确认页 OCR 明确取得原价、优惠、实付、商户和选中银行，旧确认页与成功页关联回归，结构化字段经过异步队列。测试使用独立 APK，没有把样本账单写入正式账本。
- 预览 JavaScript 语法、自动记账入口静态断言，以及优惠面板确认 / 取消 / 清空 / 冲突提示 / 详情可见性脚本检查通过。本轮未重新进行浏览器视觉交互验收。
